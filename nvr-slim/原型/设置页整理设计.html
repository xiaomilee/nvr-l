逐条说明

1
设置页只留三个分区，顺序固定：通用 → 摄像头 → 诊断与日志。 通用和诊断默认收起，各自只露一行真实摘要（通用：录像是否启用、清理时刻、压制模式、分片长度、目录；诊断：几路在录、剩余空间、未读错误数）。 摄像头是日常改动对象，永远默认展开、始终在中间，不受另外两块展开影响而上下跳。
2
摄像头行本身就是「状态 + 入口」，不再是「点开才有信息」。 每行直接给出四件事：在线点、名称、通道/分辨率/是否在录、缩时摘要胶囊（缩时 2× · 7 天 / 仅全时 / 已停用）。 每路的关键差异一眼可比，不用逐个点开。删除按钮从行内（原来紧挨着名称）移到编辑页最底部，行内只留一个 ›，从源头消掉"点错删除"。
3
编辑页改为「四段手风琴」，一次只展开一段： ① 名称与码流 ② 保留与分片 ③ 缩时压制 ④ 检测忽略区。 展开一段时其它段自动收起，折叠状态下标题行右侧始终显示该段当前值（全时 7 天 · 5 分钟、已开启 · 2× · 7 天、已选 6 格）——收起不等于失明。 好处是每一屏只面对一类参数，滑块不会紧挨着开关，纵向滚动从 3 屏缩到 1 屏多。
4
缩时压制分三层：总闸 → 常用 → 进阶。 总闸单独一条带底色的条（不是普通开关行），开关右侧只有一句后果说明；下面是四格影响预估（倍速 / 段/天 / GB每天 / 保留），改任何参数都实时变，动手前先看到代价。 常用只放 3 项：输出倍速、缩时保留、灵敏度——这三项覆盖绝大多数使用场景（占参数数量 3/11，覆盖 90% 效果）。 其余 8 项（引擎、画面类型、像素差门槛、最短事件、模糊半径、抽样帧、日夜采样、静默合并）全部收进「进阶判读参数」，收起时用一行摘要横向列出全部当前值，展开后每项单独一行滑块。
5
防误操作，四处硬约束： a关总闸 / 恢复默认 / 删除摄像头三个动作都必须过确认浮层，且浮层里写清"什么会变、什么不会变"（例如"已有 7 天缩时片段不会被删除"）。 b底部动作栏常驻不随内容滚走，左侧永远显示「已改 N 项未保存」或「最后保存 HH:MM」；有未保存改动时返回会拦一道。 c偏离默认值的进阶项标 已调，单项旁给「恢复默认」，整页底部才有"恢复这一路默认"，避免一键清掉全部调参。 d倍速 > 1 时就地提示 CPU 上升，不弹窗打断，但文字要具体（"10 秒事件压成 5 秒"）。
6
诊断与日志承接三样东西： 直播页底部那条「存储剩余/总量/保留策略 + 目录」整条搬进来，扩成一张存储卡（已用/总容量 + 全时·缩时堆叠条 + 每路占用明细 + 目录可点）； 通用设置「录制」卡里的每路录制状态整块搬进来，一行一路（圆点 / 名称 / 状态与最新分片 / 就地诊断），失败时下面直接给中文下一步建议、ffmpeg 原文收进折叠； 原有的环境自检、运行日志、导出诊断包一并留在这张页里。 直播页因此少一条 42px 的常驻底栏，四宫格画面高度直接受益。
7
危险动作在诊断页里单独隔开：「重启服务」和「清除日志」放进最底部「维护」区，用细线与上面的只读信息分开，重启走确认，清除日志按钮用红色描边。诊断页 90% 的时间只是"看"，不该让危险按钮混在查看路径里。
8
不改的部分：通用里的「录制总开关 / 清理时刻 / 目录 / 压制衔接 / 外观」内容一条不动，只是收进折叠区； 参数名、取值范围、服务端字段全部沿用现有实现（judge.* / clipSpeed / clipDays / masks.ignore），本次只做信息架构与交互层重排，不动判定引擎。
9
存储只画「录像构成」，不再出现灰色的"其余可用"。 容量是全盘共享的，按路去摊"这路还能用多少"没有意义，所以： 总条只由全时（深蓝）+ 缩时（浅蓝）两段组成，按已用体积归一（78% / 22%），剩余容量用顶部一行文字表达（剩余 1.8 TB，共 4.0 TB）； 每路那一条同样归一 —— 分子是全时 / 缩时字节，分母是这一路自己的总量，所以每行都是满格两段，读的是"这路里全时和缩时各占多少"（车库 84% / 16%、门口 65% / 35%）。 想比谁占得多就看右侧总量数字与行排序，不靠条长跨行比较。
成本控制：统计只按「摄像头 / 日期」两级目录聚合（4 路 × 30 天 ≈ 120 个目录），结果带时间戳缓存，30 分钟内最多重算一次； 只有打开诊断页且缓存过期才触发，直播、回放、其它设置页都不触发。页面写明「统计于 13:20 · 非实时」，旁边「立即重算」由用户自己按。 接口：GET /api/storage/usage（命中缓存即回，含每路 full/clip 字节与统计时刻）、POST /api/storage/usage/refresh（强制重算，按钮转"统计中…"）。
10
首页列数按钮放在刷新间隔齿轮右边，选择要记住。 齿轮管"多久刷一张"，旁边新增一颗布局按钮，点开两个选项：单列 / 双列（当前项主色高亮）。 单列 = 老样子，大画面、看得清；双列 = 一屏看到 4 路，适合巡看。切换立即生效并写入本地配置（live.cols），下次打开、重装配置保留都还是这个选择。 摄像头数量为 1 时按钮自动隐藏（单列/双列没区别）。
11
「连续播放」是一个按钮，不是一次跳转。 首页底部一条主色按钮「▶ 连续播放 · 4 路」，按下后当前这面快照墙原地换成实时流：卡片上的快照 img 换成子码流，快照轮询对这些卡片暂停，按钮变成「■ 回到快照」，右侧显示「实时 · 已播 12 分钟」。 整个过程不切页面、不重建列表、滚动位置不丢 —— 以前点任意一张图就直接进全屏播放层，想"四路一起动起来看看"反而没有入口。 某一路流起不来时只有那一格回落快照/报错，其余继续播（帧 ⑦ 第 4 格演示）。
12
点某张画面 → 单路全屏横屏播放（帧 ⑧）。 真全屏 API + 横屏锁定（不支持的 WebView 退回画面旋转铺满），进入即播；轻点画面显示/隐藏控制条： 左侧「暂停」、中间「● 实时 + 时钟」、右侧「退出全屏」，顶部还有常驻的「退出全屏」和一行状态 （直播中 · 车库入口 CH01 · 0.62 Mbps · 延迟 1.2s · ● REC 全时）——用户随时知道"在播 / 已暂停、哪一路、在不在录"。 暂停时画面冻结在最后一帧、中央出现播放键，状态行变「已暂停 · 画面冻结在最后一帧」；再点播放继续。退出全屏回到首页原来的位置与列数。
13
状态信息统一成「四个角」，首页卡片 / 连续播放 / 单路全屏共用一套： 左上 = 录制态（REC 红 / 仅预览 灰 / 已停用 / 连续播放时写 直播中），右上 = 时间戳， 左下 = 名称 + 通道号，右下 = 只在异常时出现的状态标签（快照回落 / 已暂停 / 无画面）。 异常分三级：连接中转圈计时（0.8 秒，6 秒升级）→ 回落快照（琥珀「快照 · 10s」，不冒充实时）→ 无画面（压暗 + 原因 + 单格「重试」）。 正常画面不加任何遮罩，避免状态层比画面还抢眼。
14
暂停的形态也跟着改了：首页连续播放时按「回到快照」= 整墙冻结成快照轮询（这是最自然的暂停）；单路全屏里按「暂停」= 冻结当前帧并给一个居中播放键。 不再出现"每格各压一个大播放图标"的画面（以前宫格四格就是四个图标，既挡画面又像四路各自暂停）。
